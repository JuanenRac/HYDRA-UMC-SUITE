UR16e mesh files (base.stl, shoulder.stl, upperarm.stl, forearm.stl,
wrist1.stl, wrist2.stl, wrist3.stl)

Source: https://github.com/UniversalRobots/Universal_Robots_ROS2_Description
License: BSD-3-Clause, per that repository's own LICENSE file. Official
Universal Robots repository.

upperarm.stl/forearm.stl are UR16e-specific:
  Path: meshes/ur16e/collision/{upperarm,forearm}.stl

base.stl/shoulder.stl/wrist1.stl/wrist2.stl/wrist3.stl are copies of
UR10e's own official files, NOT a mistake - that repository's own
config/ur16e/visual_parameters.yaml explicitly documents this reuse
("UR16e uses the same parts as UR10e except the upper and lower arm are
shortened"), and its own mesh path entries for base/shoulder/wrist_1/
wrist_2/wrist_3 literally point at meshes/ur10e/collision/*.stl, not
meshes/ur16e/collision/*.stl (which don't exist for those 5 links
upstream either):
  Path: meshes/ur10e/collision/{base,shoulder,wrist1,wrist2,wrist3}.stl

Downloaded verbatim, unmodified, for use in HYDRA-UMC-STUDIO's
UR16eArm.tsx 3D view. The COLLISION mesh set was used (not the higher-poly
VISUAL .dae set in the same repo) to keep bundle size down - same
STLLoader-based loading pipeline every other robot in this folder already
uses, so no new mesh format/loader was introduced.

Joint kinematic chain (origin xyz/rpy) and per-link mesh_offset come from
that repository's own config/ur16e/default_kinematics.yaml and
config/ur16e/visual_parameters.yaml directly - see
src/examples/ur16eKinematics.ts for where those exact numbers were
transcribed to. Every UR e-Series joint rotates about its own local Z axis
(ur_macro.xacro's own <axis xyz="0 0 1"/>, no exceptions), so the FK/IK
engine is shared with every other UR model in this project - see
src/examples/urKinematicsShared.ts's own header comment.
